# 道路使用許可申請書作成ツール WBS

## 1. 目的と前提

このWBSは、[課題仮説シート.md](./課題仮説シート.md)と[spec.md](./spec.md)をもとに、調査・設計・実装・検証・試行の作業を分解したものです。

- 成果物となるアプリのファイルは `index.html` 1つとし、機能ごとに分けて実装する。
- 利用者は現場を担当する社員。ChromeとEdge、インターネット接続のあるパソコンを対象とする。
- サーバーによるデータ共有は行わず、複数現場のデータを同じパソコンのブラウザー内に保存する。
- 作成時間の目標は5～10分。実際の現場担当者による試行で測定する。
- 日程・担当者・工数は、体制や優先順位が決まっていないため未設定。

## 3. 推奨する進め方と判断ポイント

1. **要件確認**：特に地図・画像の利用条件、警察署の全国判定、縮尺設定、保存容量を先に調べる。ここが決まらないと、実装方法や受入条件が変わるため。
2. **画面の骨組みと申請書**：1ページ構成と提出様式を先に確認し、書類の表示・直接編集を固める。
3. **地図・写真・作業体図**：画像取り込みから始め、縮尺設定を確定してからアイテム配置と寸法の自動更新を実装する。
4. **保存と出力**：画像を含む現場データの保存・再開を確認した後、A4印刷・PDF出力を仕上げる。
5. **実地試行**：Chrome・Edgeで検証し、現場担当者の実際の作業時間とフィードバックで改善する。

各段階の完了時に、関係者が成果物と受入条件を確認してから次へ進む。

## 4. 初期リリース前に解消する重要リスク

- **地図・写真の利用条件**：外部サービスの画像を取り込んで申請書に使えるか、無料利用を含めて確認する。条件が満たせない場合は、利用者自身が適法に用意した画像を取り込む方法を優先する。
- **警察署の全国自動判定**：無料で信頼できる全国データが見つからない可能性がある。その場合も申請作業を止めないよう、手入力の経路を用意する。
- **縮尺と寸法の整合性**：背景画像の縮尺が正しくなければ、アイテムや寸法の表示も誤る。実寸が分かる測定値を使った検証を行う。
- **ブラウザー内の画像保存容量**：画像を含む複数現場の保存には容量制限がある。上限・容量不足時の案内・データ削除を確認する。
- **申請書の正確さ**：提出先の最新様式と照合し、実際に提出する前に担当者が内容を確認できる運用を前提とする。
