# 実装開始用 引継ぎブリーフ

## 1. プロジェクト概要

道路使用許可申請書と添付書類を作成するツールを開発する。現場担当者がExcelで作業体図の図形・寸法を一つずつ作成する負担を減らし、本来の業務に使える時間を増やすことが目的。

## 2. 必ず守る開発ルール

- 初心者にも分かる日本語で説明する。不明点は作業開始前に質問する。
- アプリの成果物ファイルは **`index.html` 1つだけ**。機能ごとに役割を分け、後から一部だけ直しやすくする。
- 変更の節目ごとにコミットする。
- 詳細は [`.github/copilot-instructions.md`](../.github/copilot-instructions.md) を参照する。

## 4. MVPの目的と範囲

### MVPで確かめること

作業体図の背景に作業アイテムを配置し、寸法を設定・修正する作業を、現場担当者が現在のExcel作業より簡単に行えるか。あわせて、申請書類一式を作成し、提出用に確認・出力できる基本の流れを試す。

### MVPに含める

- 現場住所と、住所以外の申請情報の入力
- 全国共通様式に沿った申請書表紙の表示と、書類上の文字の直接編集
- 警察署名の手入力・修正（全国住所自動判定は含めない）
- 地図サービスを住所で別画面に開く導線、利用条件を確認した地図画像の取り込み
- 左右方向の現場全景写真の取り込みと写真台帳への表示
- 作業体図の背景画像取り込み（利用者が用意した平面図、または利用条件を確認した画像）
- カラーコーン、バー、作業車両等の配置・移動・サイズ変更・回転・削除
- 実測値に基づく縮尺設定、mm寸法、100mm刻みの設定、図形変更に追従する寸法表示
- 画面上の拡大・縮小
- 保存ボタンによる複数現場のブラウザー内保存・再開
- 書類ごとのA4印刷・PDF保存、ChromeとEdgeでの確認

### MVPでは行わない

- 地図・ストリートビュー画像の外部サービスからの自動取得
- 住所から警察署を全国一律に自動判定
- サーバーを使う複数端末・複数社員間の共有や同時編集
- 過去の申請データからの自動作図、必要性が確認されていない追加機能

## 5. 未決事項・実装前に判断すること

1. **外部画像の利用条件**：地図・ストリートビュー画像を取得、保存、印刷、提出書類へ掲載できるか確認する。確認できないサービス画像を利用する実装はしない。利用者自身が適切に用意した画像の取り込みを代替手段とする。
2. **作業体図の縮尺**：設定方法は未決定。実寸が分かる例で試作・比較し、採用方法と精度確認方法を実装前に決める。背景の見た目だけから実寸を保証しない。
3. **ローカル保存**：画像を含むデータの保存容量、容量不足時の案内、削除方法を確認する。ブラウザーのデータ消去で失われる可能性があるため、唯一の保管先として扱わない。
4. **申請書・添付書類**：最新様式と提出に必要な添付書類、配置、A4印刷条件を確認する。
5. **試行データ**：初期試行は個人情報・機密情報を含まないサンプルを使う。実データを使う場合は社内IT部門に事前確認する。

警察署の全国担当区域データは未調査だが、MVPでは自動判定を行わないため、後続開発の検討事項とする。

## 6. 評価の目安

- 計測区間：住所入力の開始から、必要な全書類を個別にA4印刷またはPDF保存できる状態になるまで。
- MVP目標：10分以内。5分は改善目標であり、MVPの合否条件ではない。
- 現場担当者3～5名、各自2～3件は計画上の目安。実施可能な人数・件数は試行前に調整する。
- 寸法既知のテスト図で縮尺と寸法表示を確認し、Chrome・Edge両方で編集、保存・再開、印刷を確認する。
- 重大な書類欠落、根拠ある寸法との不一致、画像の利用条件違反があれば、時間目標の達成にかかわらず試行を止めて対応する。

## 7. 推奨する実装の進め方

1. 申請様式・添付書類、画像の利用条件、縮尺案、保存条件を確認し、MVP受入条件を決める。
2. `index.html` 内でHTML・CSS・JavaScriptを役割ごとに分け、1ページの画面と申請書表紙を作る。
3. 地図リンクと、地図・左右の写真の取り込みを作る。
4. 背景画像、作図アイテム、縮尺、寸法自動更新、拡大縮小を作り、実寸既知の図で確認する。
5. ブラウザー内保存・再開と、書類ごとのA4印刷・PDF保存を作る。
6. Chrome・Edgeで確認し、サンプルを使った現場担当者の試行で時間・つまずき・フィードバックを記録する。

各段階で完了条件を確認してから次へ進む。画面作成に入る前に、特に外部画像の扱いと縮尺方法を決める。
